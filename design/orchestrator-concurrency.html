Orchestrator ticket · concurrency at a glance

Eight ways to show how many agents are working against the run's cap (maxParallel), on the real orchestrator card. Every option is shown at 0, 1, 5, 8, 9 and 10 of a cap of 10. Everything else on the card is held constant (3 of 16 merged, same title, same document) so only the concurrency element differs.

What the card shows today
  • Gold frame + dragon while the run is at work, state stripe on the left.
  • "Document run" pill, then the bouncing progress bar.
  • Run row: "5 working" in blue on the left, merged / total ("3/16") on the right.
  • Footer: the source document.
Things to watch while choosing
  • The card already carries one fraction (merged/total). A second one in the same row (A, C, F, H) is the most direct but can be misread; B, D, E and G keep the cap visual instead.
  • "At cap" (10/10) is a normal, good state, not a warning, so amber and red are out. The toggle above shows it in the frame's gold, or with no accent at all.
  • 0 working while the run is on (every remaining ticket waiting on checks, merges or dependencies) should still read as alive.

Round 2 · the count is the hero, the cap only shows when hit

Below the cap the card only says how many sessions are running; the cap itself is not shown at all. At the cap one extra cue appears, in the frame's gold. Here only the last cell (10 of 10) is at the cap; the other five look exactly like any run with that many sessions, whatever the cap is.

To pick: reply with a letter. Mixing works too, for example "A plus the pips from B" or "C, but keep the bouncing bar at 0".

Notes for implementation (nothing built yet)
  • The denominator is the run's config.maxParallel. The numerator should be the slot count (countOccupiedSlots: launching, running, checking, merging, verifying, fixing), not only "agent sessions at work", or the card will say 8/10 while the launcher refuses to start a ninth.
  • If the label keeps saying "N working" while slots are counted differently, the two numbers will disagree on the same row; one definition should win.
  • When a ticket waits for an answer the label today becomes "2 waiting for answer"; the concurrency element should survive that swap, which favours options that live outside the label (B, D, E, G).
